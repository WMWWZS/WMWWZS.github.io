这是个人思考和自我提问的方式

  1. 它是什么？(要求给出一般的范式是怎么样的)
  2. 为什么存在(它的独到之处)？
  3. 程序员视角是怎么理解的?(比如引用，这是程序员视角:
    int a = 10;
    int& r = a; -> 改r 直接影响 a)
  4. 编译器视角是怎么理解的?(这是编译器的视角，偷偷在干什么:
    int* hidden_ptr = &a;)
  5. 浅本质是什么？(比如生命周期，一个函数内的未进行修饰的变量int a，return a，它可能会变成一个未知数(危险信号)，危险访问，这就是浅的本质，表象理解)
  6. 本质上解决了什么问题(可以对比传统的)？
  7. 实际影响是什么？
  8. 有什么优点？
  9. 有什么坑？有什么限制？(这是重要的边界意识)
  10. 实际开发中最常见的用法是什么？
  11. 不这样做会怎么样?

1.0见解(基于数据类型，引用类型，函数重载，参数默认值，内联函数，C++的动态内存分配)

1.1见解(基于类的定义，对象实例化，类的构造和析构，this指针，类的静态成员，const对象和const成员函数)

1.0 this基础本质

1.仅存在于非静态成员函数，静态 static 函数无 this 指针

2.本质类型：类名* const 常量指针，指针指向不可修改

3.调用规则：哪个对象调用成员函数，this 就存该对象地址；*this = 当前对象本体

4.底层逻辑：成员函数被编译后，this 是自动隐式传入的第一个参数
